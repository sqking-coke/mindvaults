# 企业级日志规范

> 版本：v1.0 | 状态：待审批 | 适用范围：backend

## 1. 日志格式

```
YYYY-MM-DD HH:mm:ss.SSS | LEVEL | [trace_id] | [session_id] | module:method:line | message | extra
```

### 示例

```
2026-05-31 08:30:01.855 | INFO     | [a1b2c3d4e5f6a7b8] | [ses-abc123] | document_service:upload_documents:110 | doc_uploaded doc_id=8 kb_id=2 file=arch.md size=128KB
2026-05-31 08:30:01.861 | ERROR    | [a1b2c3d4e5f6a7b8] | [ses-abc123] | ingestion_service:ingest_document:23 | doc_not_found doc_id=8
2026-05-31 08:30:02.103 | INFO     | [a1b2c3d4e5f6a7b8] | [—]               | middleware:request_log:15 | request_completed method=POST path=/api/v1/kb/documents status=200 elapsed=248.3ms
```

## 2. 字段定义

| 位置 | 字段 | 类型 | 来源 | 说明 |
|------|------|------|------|------|
| 1 | `timestamp` | `YYYY-MM-DD HH:mm:ss.SSS` | 系统 | 毫秒精度 |
| 2 | `level` | `DEBUG/INFO/WARNING/ERROR` | loguru | 左对齐 8 位 |
| 3 | `trace_id` | 16 位 hex | middleware | 请求入口生成，全链路透传 |
| 4 | `session_id` | `ses-` + 8 位 / `—` | 业务代码 | 聊天会话标识，非聊天请求填 `—` |
| 5 | `location` | `module:function:line` | loguru | 代码定位 |
| 6 | `message` | `snake_case` key=value | 开发者 | 结构化消息 |

## 3. traceId 生命周期

```
┌─ 请求进入 ──────────────────────────────────────────────────┐
│  middleware:                                                 │
│    ① 读取 X-Trace-Id Header，没有则生成 uuid4().hex[:16]     │
│    ② request.state.trace_id = trace_id                      │
│    ③ logger.contextualize(trace_id=trace_id) 绑定协程        │
│                                                             │
│  路由 handler → service → db query                          │
│    ↓ 所有 loguru 调用自动携带 trace_id                       │
│                                                             │
│  响应返回:                                                   │
│    ④ response.headers[X-Trace-Id] = trace_id  ← 前端可读取  │
└─────────────────────────────────────────────────────────────┘
```

## 4. sessionId 规范

| 场景 | session_id 值 | 说明 |
|------|-------------|------|
| 聊天请求 | `req.session_id` 前 12 位 | 从 ChatRequest 取 |
| 文档上传 | `—` | 无会话上下文 |
| 配置读写 | `—` | 无会话上下文 |
| 健康检查 | `—` | 无会话上下文 |

> session_id 通过 `logger.bind(session_id=...)` 注入，不依赖 loguru contextualize。

## 5. 日志消息规范

### 格式：`action` + `key=value` 对

```
# ✅ 正确
doc_uploaded doc_id=8 kb_id=2 file=arch.md size=128KB
retrieval_completed kb_id=1 hits=5 elapsed=12ms top_similarity=0.946
llm_call_failed error="connection refused" model=deepseek-r1:8b

# ❌ 错误
文档上传成功: id=8 name=arch.md    ← 中文、冒号分隔
Document uploaded successfully       ← 英文、无结构化
```

### 关键事件命名

| 事件 | action | 携带字段 |
|------|--------|---------|
| 文档上传成功 | `doc_uploaded` | doc_id, kb_id, file, size |
| 文档解析开始 | `doc_parsing_started` | doc_id, doc_type |
| 文档解析完成 | `doc_parsing_completed` | doc_id, chunks, elapsed |
| 文档摄入失败 | `doc_ingestion_failed` | doc_id, error |
| 检索完成 | `retrieval_completed` | kb_id, query_hash, hits, elapsed, top_similarity |
| 检索空结果 | `retrieval_no_hits` | kb_id, query_hash |
| LLM 调用开始 | `llm_call_started` | model, provider, prompt_len |
| LLM 调用完成 | `llm_call_completed` | model, tokens, elapsed |
| LLM 调用失败 | `llm_call_failed` | model, error |
| 会话创建 | `session_created` | session_id, kb_id |
| 会话删除 | `session_deleted` | session_id |
| KB 创建 | `kb_created` | kb_id, name |
| KB 删除 | `kb_deleted` | kb_id |
| 请求完成 | `request_completed` | method, path, status, elapsed |

## 6. 监控预留

- 所有日志输出到文件 + stderr
- 文件按天轮转，保留 30 天
- 格式固定，适合 ELK/Loki/SLS 等日志平台采集
- `trace_id` 作为分布式追踪 key
- `session_id` 作为会话聚合 key
- 可配置 LOG_LEVEL（开发 DEBUG，生产 INFO）

## 7. 请求/响应体日志

### 7.1 格式

请求和响应体以 **单行 JSON** 输出，方便 `jq` 解析和日志平台索引：

```json
// request
{"type":"request","trace_id":"a1b2c3d4","method":"POST","path":"/api/v1/kb/chat","body":{"question":"什么是RAG","session_id":"abc123","kb_id":1}}

// response
{"type":"response","trace_id":"a1b2c3d4","status":200,"elapsed_ms":248.3,"body_preview":"event: done data: {...}"}
```

### 7.2 条件控制

| 条件 | 行为 |
|------|------|
| `LOG_LEVEL=DEBUG` | 记录完整请求体和响应体 |
| `LOG_LEVEL=INFO` | 仅记录请求摘要（method + path + body 前 200 字符） |
| `LOG_LEVEL=WARNING` | 不记录请求体，仅记录错误 |
| 请求体 > 10KB | 截断为前 200 字符 + `...(truncated)` |
| Content-Type 非 JSON | 记录 `content_type` 字段，body 存 `(binary)` |
| `/api/v1/health` | 跳过，不记录 |

### 7.3 敏感字段脱敏

JSON body 中匹配以下 key 自动脱敏后再记录：

```python
SENSITIVE_KEYS = {"api_key", "llm_api_key", "password", "authorization", "token", "secret"}

def sanitize_body(body: dict) -> dict:
    if not isinstance(body, dict): return body
    return {
        k: "***" if k in SENSITIVE_KEYS else sanitize_body(v) if isinstance(v, dict) else v
        for k, v in body.items()
    }
```

### 7.4 日志记录位置

在 `request_log_middleware` 中实现：

```python
async def request_log_middleware(request: Request, call_next):
    # 1. 读取请求体（需要缓存，因为 FastAPI 流只能读一次）
    body_bytes = await request.body()
    
    # 2. 解析并脱敏
    if body_bytes and should_log_body(request):
        try:
            body_dict = json.loads(body_bytes)
            sanitized = sanitize_body(body_dict)
            logger.bind(type="request", method=request.method,
                        path=request.url.path).info(json.dumps(sanitized, ensure_ascii=False))
        except json.JSONDecodeError:
            logger.bind(type="request", method=request.method,
                        path=request.url.path).info(json.dumps({"_raw": "(not json)"}))
    
    # 3. 重新构造 request（FastAPI 需要用新的 receive）
    ...
    
    # 4. 记录响应
    response = await call_next(request)
    ...
```

### 7.5 SSE 流式响应特殊处理

SSE 端点（`/api/v1/kb/chat`）不记录响应体（因为流式数据），改为记录事件摘要：

```json
{"type":"response","trace_id":"a1b2c3d4","status":200,"stream":"sse","events":{"progress":5,"token":42,"done":1}}
```

## 8. 日志级别约定

| 级别 | 场景 | 示例 |
|------|------|------|
| **DEBUG** | 开发调试、变量值、健康检查心跳 | `health_check_ping status=ok` |
| **INFO** | 正常业务事件 | `doc_uploaded doc_id=8`, `retrieval_completed hits=5` |
| **WARNING** | 降级行为、阈值触发、可恢复异常 | `redis_unavailable fallback=pgvector`, `retrieval_slow elapsed=823ms` |
| **ERROR** | 异常失败、需要人工关注 | `llm_call_failed error="timeout"`, `doc_ingestion_failed doc_id=8` |

> 规范写入 `CLAUDE.md`，所有开发者遵守。

## 9. 慢操作阈值

| 操作 | 阈值 | 超过后 |
|------|------|--------|
| pgvector 检索 | 500ms | WARNING `retrieval_slow` |
| LLM 首 token | 3000ms | WARNING `llm_first_token_slow` |
| 文档上传（含解析） | 30s | WARNING `ingestion_slow` |
| DB 查询 | 200ms | WARNING `db_query_slow` |
| HTTP 请求总耗时 | 5000ms | WARNING `request_slow` |

```python
# 示例：middleware 中判断请求慢
if elapsed > 5000:
    logger.bind(slow_elapsed=f"{elapsed:.0f}").warning("request_slow")
elif elapsed > 200:
    logger.info("request_completed")
```

## 10. 健康检查降噪

`GET /api/v1/health` 和 `GET /api/v1/health/system` 请求：
- 不记录 INFO 日志
- 仅在失败时记录 ERROR
- 避免日志文件被心跳淹没

```python
# middleware 中判断
if request.url.path.startswith("/api/v1/health"):
    if response.status_code >= 400:
        logger.error(f"health_check_failed status={response.status_code}")
    # 正常心跳不记录
```

## 11. 敏感信息脱敏

日志中出现以下字段时自动脱敏：

| 字段 | 原始值 | 日志输出 |
|------|--------|---------|
| `api_key` | `sk-fcc2c26004b4424989952a6adb2b2825` | `sk-••••2825` |
| `llm_api_key` | `sk-abc123def456` | `sk-••••f456` |
| `password` | 任意值 | `***` |
| `authorization` header | `Bearer xxx` | `Bearer ••••` |

```python
# 工具函数
def mask_secret(value: str, keep: int = 4) -> str:
    if not value or len(value) <= keep: return "***"
    return f"{value[:keep]}••••{value[-keep:]}"
```

## 12. 错误日志规范

ERROR 日志必须携带以下最小信息集：

```
action error="{message}" traceback_last="{file}:{line}" trace_id={...}
```

```python
# ✅ 正确
except Exception as exc:
    tb = exc.__traceback__
    while tb.tb_next: tb = tb.tb_next
    logger.error(
        f"llm_call_failed error=\"{exc}\" traceback_last=\"{tb.tb_frame.f_code.co_filename}:{tb.tb_lineno}\""
    )

# ❌ 错误
logger.error(f"调用失败: {exc}")           # 中文、无定位
logger.exception("LLM call failed")         # 无结构化
```

## 13. 监控指标预留字段

以下字段供日志平台聚合告警：

| 指标 | 日志 key | 聚合方式 | 告警条件 |
|------|---------|---------|---------|
| 请求 QPS | `request_completed` 事件计数 | `rate(1m)` | > 100/s |
| 错误率 | `level=ERROR` 占比 | `sum(ERROR)/sum(all)` | > 5% |
| 检索 P99 | `retrieval_completed elapsed` | `histogram_quantile(0.99)` | > 1s |
| LLM 可用率 | `llm_call_completed / llm_call_started` | 比值 | < 95% |
| 文档摄入成功率 | `doc_ingestion_failed / doc_uploaded` | 比值 | < 90% |
| KB 删除告警 | `kb_deleted` | 直接计数 | > 0（可能是误操作） |

## 14. 公共日志工具类

所有日志操作封装到 `app/utils/logger.py`，业务代码不直接调用 `loguru.logger`。

### 14.1 模块结构

```python
# app/utils/logger.py

import json
from loguru import logger

# --- 脱敏 ---
SENSITIVE_KEYS = {"api_key", "llm_api_key", "password", "authorization", "token", "secret"}

def mask_secret(value: str, keep: int = 4) -> str: ...

def sanitize_body(body: dict) -> dict: ...

# --- 上下文绑定 ---
def bind_trace(trace_id: str): ...
def bind_session(session_id: str | None): ...

# --- 请求/响应日志 ---
def log_request_body(body: dict, method: str, path: str, trace_id: str): ...
def log_response(status: int, elapsed_ms: float, trace_id: str, body_preview: str = ""): ...

# --- 业务事件日志 ---
def log_event(action: str, **kwargs): ...

# --- 条件控制 ---
def should_log_body(request) -> bool: ...
def is_health_check(path: str) -> bool: ...
```

### 14.2 核心方法签名

```python
def log_event(action: str, **kwargs) -> None:
    """
    记录业务事件。
    用法:
      from app.utils.logger import log_event
      log_event("doc_uploaded", doc_id=8, kb_id=2, file="arch.md", size="128KB")
    输出:
      doc_uploaded doc_id=8 kb_id=2 file=arch.md size=128KB
    """
    msg = action + " " + " ".join(f"{k}={v}" for k, v in kwargs.items())
    logger.info(msg)

def log_request_body(body: dict, method: str, path: str, trace_id: str) -> None:
    """DEBUG 模式下记录请求体（JSON 单行、脱敏）。"""
    sanitized = sanitize_body(body)
    logger.bind(type="request", trace_id=trace_id, method=method, path=path).debug(
        json.dumps(sanitized, ensure_ascii=False)
    )

def bind_trace(trace_id: str):
    """绑定 trace_id 到当前协程上下文。"""
    logger.configure(extra={"trace_id": trace_id})

def bind_session(session_id: str | None):
    """绑定 session_id 到当前协程上下文。"""
    logger.configure(extra={"session_id": session_id or "—"})
```

### 14.3 业务代码调用示例

```python
# 改造前（直接调用 logger）
logger.info(f"文档上传成功: id={doc.id} name={doc.doc_name} kb_id={kb_id}")

# 改造后（调用封装方法）
from app.utils.logger import log_event
log_event("doc_uploaded", doc_id=doc.id, kb_id=kb_id, file=doc.doc_name)
```
