# 07 - 大模型动态切换设计

> 来源：06-model-switching-design.md | 状态：✅ 已实现

## 1. 设计目标

在本地 Ollama 和云端 API 之间灵活切换，支持热更新（无需重启），持久化配置到数据库。

## 2. 数据存储

模型配置分两层存储：

### 2.1 全局默认配置 — `system_config` 表（单行，id=1）

`GET/PUT /api/v1/kb/config` 读写此表。`chat_service` 和 `ingestion_service` 优先读取此表，字段为 NULL 时回退到环境变量。

| 字段 | 类型 | 说明 |
|------|------|------|
| `llm_provider` | VARCHAR(50) | `ollama` / `openai` |
| `llm_base_url` | VARCHAR(255) | API 基址 |
| `llm_model` | VARCHAR(100) | 模型名称 |
| `llm_api_key` | VARCHAR(255) | 云端 API 密钥 |
| `llm_temperature` | FLOAT | 采样温度 (0.0-1.5)，默认 0.3 |
| `system_prompt` | TEXT | 全局系统提示词 |
| `embedding_provider` | VARCHAR(50) | Embedding 提供商，默认 `same_as_llm` |
| `embedding_base_url` | VARCHAR(255) | Embedding API 基址 |
| `embedding_api_key` | VARCHAR(255) | Embedding API 密钥 |
| `embedding_model` | VARCHAR(100) | Embedding 模型名称 |

### 2.2 KB 级配置 — `kb_config` 表（每 KB 一行）

`GET/PUT /api/v1/kb/knowledge-bases/{id}/config` 读写此表。存储每个 KB 独立的检索参数（chunk_size、top_k 等）+ 可选的 KB 级 LLM 覆盖（字段名与 system_config 一致）。

### 配置优先级

```
system_config.字段 → 环境变量 → settings 默认值
```

## 3. 模型列表获取

### Ollama 模式

```
GET /api/v1/kb/config/ollama-models
  → 后端代理请求 Ollama GET /api/tags
    → 返回本地已下载模型列表 ["deepseek-r1:8b", "qwen2.5:7b", ...]
    → 连接失败则返回空数组（不报 500）
```

### 云端 API 模式

前端预设列表 + 自定义输入：
- 预设：`deepseek-v4-pro`, `deepseek-v4-flash`, `gpt-4o`, `gpt-3.5-turbo`
- 用户在设置面板输入的自定义模型名保存后自动加入切换列表

## 4. 前后端交互

### 4.1 全局 LLM 配置切换

```
[设置面板 / 快速切换下拉框]
  │ 用户选择模型
  ▼
updateSystemConfig({ llm_model: "deepseek-r1:8b" })
  │ PUT /api/v1/kb/config        ← 写入 system_config 表
  ▼
system_config.llm_model = "deepseek-r1:8b"
  │ 下次问答请求
  ▼
chat_service.py: 读取 SystemConfig → generate_stream(model="deepseek-r1:8b")
```

### 4.2 两种配置端点的区别

| 端点 | 目标表 | 用途 |
|------|--------|------|
| `GET/PUT /api/v1/kb/config` | `system_config` | 全局 LLM/Embedding 默认配置 |
| `GET/PUT /api/v1/kb/knowledge-bases/{id}/config` | `kb_config` | KB 级检索参数 + 可选 LLM 覆盖 |

## 5. 安全设计

- **API Key 脱敏**：`GET /api/v1/kb/config` 返回 `sk-••••••••xxxx`，`llm_api_key` 和 `embedding_api_key` 均脱敏，明文仅存在数据库
- **保存时判断**：如果传入的 key 含 `••`（打码版），跳过更新保留原值
- **本地模式隔离**：Ollama 模式下请求全程回环网口 `127.0.0.1:11434`，不经过外网
