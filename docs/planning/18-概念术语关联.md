# 概念/术语关联 — 方案设计

> 状态：✅ 方案已确定 | 创建：2026-06-02 | 关联：[[15-KB智能路由]] [[05-数据库设计]]

## 问题

知识库文档中散布大量专业术语（如"质心向量匹配""HNSW 索引""余弦距离"），当前系统：
- 术语含义对读者不透明，需要离开系统自行搜索
- LLM 回答时缺少术语上下文，可能误解或简化概念
- 概念之间没有关联，知识库是孤立的文档堆，不是知识网络

## 目标

把知识库从"文档堆"变成"可导航的知识网络"：

```
文档 chunk "...采用质心向量匹配..."
    │
    ├── 关联 → 概念 "质心向量匹配"（定义 + 相关概念 + 引用文档）
    │
    └── RAG 检索命中时 → 概念定义注入上下文 → LLM 更准确理解术语
```

---

## 关键设计决策

| 决策 | 结论 |
|------|------|
| 概念来源 | **LLM 自动抽取**：文档摄入时从 chunk 提取术语 + 生成定义 |
| 存储 | **独立表 `kb_concepts`** + 关联表 `kb_chunk_concepts` |
| 抽取时机 | **摄入时**：chunk → embed → LLM 提取术语 → 建概念 + 关联 |
| RAG 增强 | **注入上下文**：检索命中的 chunk 关联的概念定义注入 LLM 上下文 |
| 定义长度 | 注入时用摘要（≤200 字），hover 时展示完整定义 |
| 前端交互 | **阅读时 hover**：文档/回答中术语下划线，hover 弹概念卡片 |

## 数据库设计

### `kb_concepts` — 概念表

```sql
CREATE TABLE kb_concepts (
    id              BIGSERIAL PRIMARY KEY,
    kb_id           BIGINT NOT NULL REFERENCES kb_knowledge_bases(id) ON DELETE CASCADE,
    
    -- 概念标识
    name            VARCHAR(200) NOT NULL,           -- 术语名，如 "质心向量匹配"
    aliases         VARCHAR(100)[],                   -- 别名/同义词，如 ["centroid matching", "KB 质心"]
    
    -- 内容
    definition      TEXT NOT NULL,                    -- 完整定义
    summary         VARCHAR(500),                     -- 一句话摘要，注入 LLM 上下文用
    
    -- 向量
    embedding       vector(1024),                     -- 概念名 + 定义的向量
    
    -- 来源
    source_chunk_ids BIGINT[],                        -- 首次抽取时来自哪些 chunk
    
    -- 状态
    status          VARCHAR(20) NOT NULL DEFAULT 'auto',  -- auto(自动抽取) / confirmed(已确认) / edited(已编辑)
    confidence      FLOAT NOT NULL DEFAULT 0.0,       -- LLM 抽取时的置信度
    
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_concepts_kb ON kb_concepts(kb_id);
CREATE UNIQUE INDEX idx_concepts_kb_name ON kb_concepts(kb_id, LOWER(name));
CREATE INDEX idx_concepts_embedding_hnsw ON kb_concepts
    USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 200);
```

### `kb_chunk_concepts` — chunk-概念关联表

```sql
CREATE TABLE kb_chunk_concepts (
    id              BIGSERIAL PRIMARY KEY,
    chunk_id        BIGINT NOT NULL REFERENCES kb_chunks(id) ON DELETE CASCADE,
    concept_id      BIGINT NOT NULL REFERENCES kb_concepts(id) ON DELETE CASCADE,
    relevance       FLOAT NOT NULL DEFAULT 1.0,      -- 该术语在 chunk 中的相关度
    position        INT[],                             -- 术语在 chunk 中出现的位置（字符偏移）
    
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    
    UNIQUE (chunk_id, concept_id)
);

CREATE INDEX idx_chunk_concepts_chunk ON kb_chunk_concepts(chunk_id);
CREATE INDEX idx_chunk_concepts_concept ON kb_chunk_concepts(concept_id);
```

## 概念抽取流程

### 摄入时自动抽取

```
文档上传 → 解析 → 切 chunk
    │
    ▼
逐 chunk 处理：
    │
    ├── 1. embed chunk → 写入 kb_chunks
    │
    └── 2. LLM 术语抽取（非流式，temperature=0）
            │
            System: 你是一个术语抽取助手。从以下文档片段中提取专业术语，
                    为每个术语生成简洁定义，返回 JSON 数组。
                    
                    要求：
                    - 只提取领域特定的专业术语，不提取通用词汇
                    - 定义长度 ≤ 500 字，自包含，不需要上下文就能理解
                    - 同时生成一条 ≤ 100 字的摘要（用于注入 LLM 上下文）
                    - 如果片段没有值得提取的术语，返回空数组
                    - 术语要有别名（英文缩写、常见别称）
            
            User: [chunk content]
            
            Response:
            [{
              "name": "质心向量匹配",
              "aliases": ["centroid matching", "KB 质心"],
              "definition": "质心向量匹配是一种知识库路由方法...",
              "summary": "通过计算 KB 中所有 chunk 向量的均值作为质心，用余弦距离判断用户问题最匹配哪个知识库。",
              "confidence": 0.9,
              "positions": [[45, 53], [120, 128]]
            }, ...]
            │
            ▼
        3. 去重 + 写入
            │
            ├── 概念名 + kb_id 查 kb_concepts 是否已存在
            │   ├── 不存在 → INSERT 新概念
            │   └── 已存在 → 更新 definition（如果新版本置信度更高）
            │               合并 source_chunk_ids
            │
            └── INSERT INTO kb_chunk_concepts (chunk_id, concept_id, relevance, position)
```

### 成本考虑

| 环节 | 额外开销 | 优化 |
|------|---------|------|
| 术语抽取 LLM 调用 | 每 chunk 一次 | 仅对 ≥ 500 字符的 chunk 抽取；小 chunk 跳过 |
| 去重查询 | < 1ms | `LOWER(name)` 唯一索引 |
| 概念 embedding | ~50ms/概念 | 仅新建概念时计算 |

**批量优化**：一次 LLM 调用处理多个 chunk（如 3-5 个），减少 API 往返。或者用更便宜的模型做术语抽取（和主 QA 的 embedding/LLM 无关）。

## RAG 上下文注入

### 注入规则

检索命中 chunk → 查关联概念 → 按规则注入：

```
检索结果：
  chunk_A (匹配度 0.85) → 关联概念 [质心向量匹配, pgvector]
  chunk_B (匹配度 0.72) → 关联概念 [HNSW 索引]

注入 LLM 的上下文：
  参考文档：
  
  [术语说明] 相关概念：
  - 质心向量匹配：通过计算 KB 中所有 chunk 向量的均值作为质心，用余弦距离判断...
  - pgvector：PostgreSQL 向量扩展，支持 HNSW 索引和余弦距离查询。
  - HNSW 索引：分层可导航小世界图，一种近似最近邻搜索算法...
  
  [文档 1] chunk_A 内容...
  [文档 2] chunk_B 内容...
```

### 注入策略

| 规则 | 说明 |
|------|------|
| **去重** | 多个 chunk 关联同一概念，只注入一次 |
| **截断** | 每个概念注入摘要（≤200 字），不是完整定义 |
| **上限** | 每轮最多注入 5 个概念，超出按 chunk 匹配度排序截断 |
| **排序** | 按 chunk 匹配度降序，匹配度高的 chunk 关联的概念优先 |
| **位置** | 概念说明放在文档内容**前面**，LLM 先读术语再读文档 |

### 注入代码位置

`chat_service.py` → `_build_context(chunks)` 改造：

```python
def _build_context(chunks: list[RefChunk], concepts: dict[str, str]) -> str:
    parts = []
    
    # 先放术语说明
    if concepts:
        parts.append("[术语说明]\n")
        for name, summary in concepts.items():
            parts.append(f"- {name}: {summary}")
        parts.append("")
    
    # 再放文档内容
    for i, c in enumerate(chunks, 1):
        parts.append(f"[{i}] 来源: {c.doc_name}\n{c.content}")
    
    return "\n\n".join(parts)
```

## 前端交互

### Hover 概念卡片

聊天回答中，已关联概念的术语自动加下划线，hover 弹卡片：

```
LLM 回答：
"...系统采用 质心向量匹配 技术，通过 pgvector 的 余弦距离..."
              ════════════              ────────       ════════
              
hover "质心向量匹配" → ┌─────────────────────────┐
                      │ 质心向量匹配              │
                      │                          │
                      │ 通过计算 KB 中所有 chunk   │
                      │ 向量的均值作为质心...      │
                      │                          │
                      │ 📄 相关文档：              │
                      │  15-KB智能路由.md         │
                      │  05-数据库设计.md         │
                      │                          │
                      │ 🔗 相关概念：              │
                      │  pgvector, 余弦距离       │
                      └─────────────────────────┘
```

### 实现方式

前端收到完整回答后，扫一遍文本，匹配已加载的 `kb_concepts` 列表中的术语名，自动添加 hover 标记。因为是客户端后处理，不影响 SSE 流式体验。

### 概念管理页

```
知识库侧边栏：
  📚 文档
  💬 对话
  🏷️ 概念（新增 tab）→ 概念列表页
```

概念列表页支持：搜索、按状态筛选、编辑定义、删除、手动新增。

## 配置项

放在 `system_config` 中：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `concept_extraction_enabled` | `true` | 是否启用概念自动抽取 |
| `concept_min_chunk_length` | `500` | 小于此长度的 chunk 跳过抽取 |
| `concept_max_per_round` | `5` | 每轮 RAG 最多注入几个概念 |
| `concept_summary_max_length` | `200` | 注入上下文时的摘要最大字符数 |
