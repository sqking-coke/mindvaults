# 05 - 数据库设计

> 状态：✅ 已实施 | 版本：v2.1 多知识库架构 | 迁移：0004 → 0008

## 1. 设计原则

- **KB 级隔离**：文档 → 切片 → 会话 → QA 记录，通过 `kb_id` 层层归属
- **每 KB 独立配置**：`kb_config` 以 `kb_id` 作 PK+FK，一对一
- **级联删除**：删 KB → 级联删文档 → 级联删切片
- **无软删除扩散**：只有 `kb_documents.deleted_at` 用软删除，其他物理删除
- **预留扩展**：`kb_data_sources` / `kb_raw_entries` / `kb_feedback` 三张表本期建好，后期接定时任务和反馈学习

## 2. ER 图

```
kb_knowledge_bases (1) ──── (1) kb_config          ← KB + 独立配置
       │
       │ (1:N)
       ├── kb_documents (N) ──── (1:N) kb_chunks ← 文档 + 切片
       │
       │ (1:N)
       ├── kb_sessions (N) ──── (1:N) kb_qa_records  ← 会话 + QA
       │
       │ (1:N)
       ├── kb_data_sources (N) ─── (1:N) kb_raw_entries ← 外部数据源（预留）
       │
       └── kb_feedback (N)                          ← 反馈学习（预留）
```

## 3. 完整 DDL

### 3.1 知识库主表

```sql
CREATE TABLE kb_knowledge_bases (
    id          BIGSERIAL PRIMARY KEY,
    name        VARCHAR(255) NOT NULL,
    description TEXT DEFAULT '',
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 3.2 知识库配置表（一对一）

```sql
-- 每 KB 一行配置，kb_id 既是 PK 也是 FK
CREATE TABLE kb_config (
    kb_id               BIGINT PRIMARY KEY REFERENCES kb_knowledge_bases(id) ON DELETE CASCADE,
    embedding_dim       INTEGER NOT NULL DEFAULT 1024,
    chunk_size          INTEGER NOT NULL DEFAULT 500,
    chunk_overlap       INTEGER NOT NULL DEFAULT 50,
    top_k               INTEGER NOT NULL DEFAULT 5,
    similarity_threshold FLOAT NOT NULL DEFAULT 0.35,

    -- LLM 配置
    llm_provider        VARCHAR(50),        -- ollama / openai
    llm_base_url        VARCHAR(255),
    llm_model           VARCHAR(100),
    llm_api_key         VARCHAR(255),
    llm_temperature     FLOAT NOT NULL DEFAULT 0.3,
    system_prompt       TEXT,

    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 3.3 文档表

```sql
CREATE TABLE kb_documents (
    id          BIGSERIAL PRIMARY KEY,
    kb_id       BIGINT NOT NULL REFERENCES kb_knowledge_bases(id) ON DELETE CASCADE,
    doc_name    VARCHAR(255) NOT NULL,
    doc_type    VARCHAR(10) NOT NULL,        -- txt / md / pdf / docx / doc
    doc_desc    TEXT,
    file_path   VARCHAR(500) NOT NULL,
    status      SMALLINT NOT NULL DEFAULT 1, -- 0=失败 1=解析中 2=成功 3=禁用
    chunk_count INTEGER NOT NULL DEFAULT 0,
    source      VARCHAR(50),                 -- obsidian / upload / api (数据来源)
    file_size   BIGINT NOT NULL DEFAULT 0,   -- 物理文件字节数，上传时 stat 写入
    status_detail JSONB NOT NULL DEFAULT '{}', -- 摄入心跳: {"phase":"embedding","total":200}
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at  TIMESTAMPTZ                  -- 软删除
);

CREATE INDEX idx_documents_kb_id ON kb_documents(kb_id);
CREATE INDEX idx_documents_status ON kb_documents(status);
CREATE INDEX idx_documents_deleted ON kb_documents(deleted_at);
```

### 3.4 切片表

```sql
CREATE TABLE kb_chunks (
    id          BIGSERIAL PRIMARY KEY,
    document_id BIGINT NOT NULL REFERENCES kb_documents(id) ON DELETE CASCADE,
    chunk_index INTEGER NOT NULL,
    content     TEXT NOT NULL,
    embedding   vector(1024),               -- pgvector，1024维
    page        INTEGER,                    -- PDF 页码
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_chunks_document ON kb_chunks(document_id);
CREATE INDEX idx_chunks_embedding_hnsw ON kb_chunks
    USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 200);
```

### 3.5 会话表

```sql
CREATE TABLE kb_sessions (
    id          BIGSERIAL PRIMARY KEY,
    session_id  VARCHAR(36) UNIQUE NOT NULL, -- UUID
    kb_id       BIGINT NOT NULL REFERENCES kb_knowledge_bases(id) ON DELETE CASCADE,
    title       VARCHAR(255) NOT NULL DEFAULT '新对话',
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE UNIQUE INDEX idx_sessions_uuid ON kb_sessions(session_id);
CREATE INDEX idx_sessions_kb ON kb_sessions(kb_id);
```

### 3.6 QA 记录表

```sql
CREATE TABLE kb_qa_records (
    id          BIGSERIAL PRIMARY KEY,

    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()

CREATE INDEX idx_qa_session ON kb_qa_records(session_id);
```


### 3.8 原始数据暂存表（本期建表，P2 启用）

```sql
CREATE TABLE kb_raw_entries (

    kb_id           BIGINT NOT NULL REFERENCES kb_knowledge_bases(id) ON DELETE CASCADE,
    raw_content     TEXT NOT NULL,
```

```sql
CREATE TABLE kb_feedback (
```

## 4. 索引策略

| 表 | 索引 | 类型 | 用途 |
|----|------|------|------|
| kb_documents | `kb_id` | B-tree | 按 KB 过滤文档 |
| kb_documents | `status` | B-tree | 按状态过滤 |
| kb_documents | `deleted_at` | B-tree | 排除已删除 |
| kb_chunks | `document_id` | B-tree | 按文档查切片 |
| kb_chunks | `embedding` | **HNSW** | 向量相似度检索 |
| kb_sessions | `session_id` | UNIQUE B-tree | UUID 查会话 |
| kb_sessions | `kb_id` | B-tree | 按 KB 隔离会话 |
| kb_qa_records | `session_id` | B-tree | 按会话查历史 |
| kb_qa_records | `created_at` | B-tree | 时序查询/统计 |

## 5. 检索查询（核心 SQL）

```sql
-- 限定 KB 的向量检索
SET hnsw.ef_search = 40;

SELECT
    c.id AS chunk_id,
    d.doc_name,
    c.content,
    1 - (c.embedding <=> :query_vec) AS similarity,
    c.page
FROM kb_chunks c
JOIN kb_documents d ON c.document_id = d.id
WHERE d.deleted_at IS NULL
  AND d.status = 2                    -- COMPLETED
  AND d.kb_id = :kb_id               -- ★ KB 隔离
  AND 1 - (c.embedding <=> :query_vec) >= :threshold
ORDER BY similarity DESC
LIMIT :top_k;
```

## 9. 应用层事务规范

> 补充于 2026-05-31

### 核心原则

**任何 `db.add()` + `db.flush()` 后，所有代码路径必须显式 `commit()` 或 `rollback()`，不得依赖会话垃圾回收。**

SQLAlchemy async session 的 `close()` 会回滚未提交事务，但该时机不可控（依赖 ASGI 任务回收），期间持有的行级锁会阻塞后续请求。

### 典型 Bug 模式

**模式 1：early return 未提交**

```python
# ❌ db.flush() 后直接 return，未提交 → 行级锁未释放
db.add(record)
await db.flush()
if error:
    return  # 💀

# ✅ 每个 return 前显式提交或回滚
db.add(record)
await db.flush()
if error:
    await db.commit()  # 或 rollback()
    return
```

**模式 2：生成器中长时间持锁**

```python
# ❌ flush 后等 30s+ 的外部调用才 commit
db.add(session)
await db.flush()
result = await llm_call()  # 一直持锁
await db.commit()           # 太晚了

# ✅ 外部调用前立即提交
db.add(session)
await db.flush()
await db.commit()           # 释放锁
result = await llm_call()   # 新事务，不持锁
```

**模式 3：循环中 flush 失败后未回滚**

```python
# ❌ flush 失败后会话损坏，下一轮 db.add() 必然失败
for item in items:
    try:
        db.add(record)
        await db.flush()
    except Exception:
        failed += 1          # 💀 未回滚，会话已损坏

# ✅ 异常时回滚重置会话
for item in items:
    try:
        db.add(record)
        await db.flush()
    except Exception:
        await db.rollback()  # 重置会话状态
        failed += 1
```

**模式 4：getter 中的隐式写入未提交**

```python
# ❌ 创建默认行后未提交，依赖调用者 → GET 端点调用者不提交
async def get_config(db, kb_id):
    row = await db.execute(select(...))
    if row is None:
        row = KbConfig(kb_id=kb_id)
        db.add(row)
        await db.flush()     # 💀 未提交
    return row

# ✅ 自包含事务
async def get_config(db, kb_id):
    row = await db.execute(select(...))
    if row is None:
        row = KbConfig(kb_id=kb_id)
        db.add(row)
        await db.flush()
        await db.commit()    # 立即提交
    return row
```
