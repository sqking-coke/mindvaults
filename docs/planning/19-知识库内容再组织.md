# 知识库内容再组织 — 方案设计

> 状态：✅ 方案已确定 | 创建：2026-06-02 | 关联：[[16-对话知识沉淀]] [[18-概念术语关联]]

## 问题

知识库长期使用后出现四类退化：
1. **碎片化** — 同一知识点散落在多个 chunk（来自不同文档/insight），检索命中随机
2. **低质量** — 短 chunk、空壳内容占据检索位，好内容被挤出 top_k
3. **过时** — 旧版本、已废弃的信息仍在库中，LLM 可能引用
4. **孤岛** — chunk 的源文档已删除但未清理，或 insight 被拒绝但 chunk 还在

## 目标

提供诊断 → 决策 → 执行的知识库治理能力，而非粗暴的自动化。

---

## 关键设计决策

| 决策 | 结论 |
|------|------|
| 处理模式 | **诊断报告 + 用户决策**：系统检测问题并推荐方案，用户确认后执行 |
| 自动化边界 | 相似度 > 0.98 且双方都来自同一文档 → 自动合并；其余需用户确认 |
| 检测类型 | 多维度检测：近重复、低质量、可能过时、孤岛、碎片簇 |
| 合并策略 | **保留优者**：按质量评分选最优 chunk，其余标记为 superseded |
| 触发时机 | **三维触发**：摄入时即时检测 + 定期全库扫描 + 手动触发 |

## 检测类型

### 1. 近重复检测

```
SELECT c1.id, c2.id, 1 - (c1.embedding <=> c2.embedding) AS sim
FROM kb_chunks c1, kb_chunks c2
WHERE c1.kb_id = :kb_id
  AND c2.kb_id = :kb_id
  AND c1.id < c2.id
  AND 1 - (c1.embedding <=> c2.embedding) > :threshold  -- 默认 0.92
ORDER BY sim DESC;
```

| 检测到 | 推荐方案 |
|--------|---------|
| sim > 0.98，同一文档 | 自动合并（保留长的） |
| sim > 0.92，不同来源 | 推荐merge，用户选择保留哪个 |
| sim 0.85-0.92 | 标记"主题相近"，建议链接 |

### 2. 低质量检测

```sql
SELECT id, content, LENGTH(content) AS len
FROM kb_chunks
WHERE kb_id = :kb_id
  AND LENGTH(content) < :min_length;  -- 默认 100
```

额外规则：
- 纯标点/数字占比 > 50% → 低质量
- 内容全是代码块但没有说明 → 低质量
- insight 被拒绝但 chunk 仍在 → 低质量

### 3. 过时检测

| 信号 | 检测方式 |
|------|---------|
| 旧版本号 | 正则匹配 `Python [23]\.[0-7]`、`v[0-2]\.[0-9]` 等 |
| 文档新版本 | 同一 `doc_name` 有更新版本上传，旧 chunk 时间戳早于新文档 |
| 时间衰减 | chunk 创建超过 1 年且从未被检索命中过 → 建议复核 |

### 4. 孤岛检测

```sql
-- chunk 关联的文档已被软删除
SELECT c.id FROM kb_chunks c
JOIN kb_documents d ON c.document_id = d.id
WHERE d.deleted_at IS NOT NULL;

-- insight chunk 对应的 insight 已被拒绝
SELECT c.id FROM kb_chunks c
JOIN kb_insights i ON c.source_insight_id = i.id
WHERE i.status = 'rejected';
```

### 5. 碎片簇检测

主题相近但不重复的一组 chunk，建议用户手动定义主题簇：

```
检测到 6 个 chunk 围绕 "Django ORM 性能优化"：
  chunk_A: "Django ORM 的 select_related..."
  chunk_B: "优化 Django 查询：prefetch_related..."
  chunk_C: "ORM 查询次数过多？用 django-debug-toolbar..."
  chunk_D: "Django 数据库索引优化..."
  chunk_E: "N+1 查询问题的 5 种解决方案..."
  chunk_F: "QuerySet 懒加载机制详解..."

推荐：创建主题簇「Django ORM 性能优化」，用户可一键链接这 6 个 chunk
      → 检索命中任一个时，附带展示簇内其他标题
```

## 质量评分体系

合并时"保留优者"，需要一个评分模型：

```python
def compute_quality_score(chunk) -> float:
    """计算 chunk 质量分，0-1。"""
    score = 0.0
    
    # 1. 内容长度 (0-0.25)
    score += min(len(chunk.content) / 1000, 1.0) * 0.25
    
    # 2. 引用热度 (0-0.30) — 在 QA 中被检索命中的次数
    hit_count = get_hit_count(chunk.id)
    score += min(hit_count / 20, 1.0) * 0.30
    
    # 3. 概念关联数 (0-0.20) — 关联的概念越多，信息密度越高
    concept_count = get_concept_count(chunk.id)
    score += min(concept_count / 5, 1.0) * 0.20
    
    # 4. 时效性 (0-0.15) — 越新越好
    age_days = (now() - chunk.created_at).days
    score += max(0, 1.0 - age_days / 365) * 0.15
    
    # 5. 来源权威性 (0-0.10) — insight(确认过的) > 文档 > insight(auto)
    source_weight = {"insight_confirmed": 1.0, "document": 0.7, "insight_auto": 0.4}
    score += source_weight.get(chunk.source_type, 0.5) * 0.10
    
    return round(score, 4)
```

> 注：引用热度需要新增统计机制。可以在 `kb_chunks` 加 `hit_count` 字段，检索命中时异步累加。

## 数据库改动

### `kb_chunks` 补充字段

```sql
ALTER TABLE kb_chunks
  ADD COLUMN quality_score FLOAT NOT NULL DEFAULT 0.0,    -- 质量分
  ADD COLUMN status VARCHAR(20) NOT NULL DEFAULT 'active', -- active / superseded / archived / orphan
  ADD COLUMN superseded_by BIGINT REFERENCES kb_chunks(id), -- 被哪个 chunk 取代
  ADD COLUMN source_type VARCHAR(30) NOT NULL DEFAULT 'document', -- document / insight_confirmed / insight_auto
  ADD COLUMN source_insight_id BIGINT,                     -- 来自哪个 insight
  ADD COLUMN hit_count INTEGER NOT NULL DEFAULT 0,        -- 检索命中次数
  ADD COLUMN last_hit_at TIMESTAMPTZ;                     -- 最后命中时间
```

### `kb_health_reports` — 诊断报告

```sql
CREATE TABLE kb_health_reports (
    id              BIGSERIAL PRIMARY KEY,
    kb_id           BIGINT NOT NULL REFERENCES kb_knowledge_bases(id) ON DELETE CASCADE,
    
    scan_type       VARCHAR(20) NOT NULL,           -- scheduled / manual / ingestion
    scanned_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    
    total_chunks    INTEGER NOT NULL,
    duplicate_groups INTEGER NOT NULL DEFAULT 0,    -- 疑似重复组数
    low_quality     INTEGER NOT NULL DEFAULT 0,     -- 低质量 chunk 数
    outdated        INTEGER NOT NULL DEFAULT 0,     -- 可能过时数
    orphans         INTEGER NOT NULL DEFAULT 0,     -- 孤岛数
    fragment_clusters INTEGER NOT NULL DEFAULT 0,   -- 碎片簇数
    
    health_score    FLOAT NOT NULL DEFAULT 100.0,   -- 健康度 0-100
    
    details_json    JSONB NOT NULL DEFAULT '{}',    -- 详细检测结果
    resolved_at     TIMESTAMPTZ,                    -- 全部处理完成时间
    
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_health_reports_kb ON kb_health_reports(kb_id);
CREATE INDEX idx_health_reports_kb_time ON kb_health_reports(kb_id, scanned_at DESC);
```

### `kb_chunk_links` — chunk 间关联

```sql
CREATE TABLE kb_chunk_links (
    id              BIGSERIAL PRIMARY KEY,
    kb_id           BIGINT NOT NULL REFERENCES kb_knowledge_bases(id) ON DELETE CASCADE,
    source_chunk_id BIGINT NOT NULL REFERENCES kb_chunks(id) ON DELETE CASCADE,
    target_chunk_id BIGINT NOT NULL REFERENCES kb_chunks(id) ON DELETE CASCADE,
    
    link_type       VARCHAR(20) NOT NULL,           -- supersedes / related / cluster
    
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    
    UNIQUE (source_chunk_id, target_chunk_id, link_type)
);

CREATE INDEX idx_chunk_links_source ON kb_chunk_links(source_chunk_id);
CREATE INDEX idx_chunk_links_target ON kb_chunk_links(target_chunk_id);
```

## 触发时机

| 时机 | 触发条件 | 扫描范围 | 说明 |
|------|---------|---------|------|
| **摄入时** | 新文档/insight 入库后 | 仅新内容 vs 存量 | 检测新增内容是否和存量重复，即时提示用户 |
| **定期扫描** | 每周日凌晨 3:00 | 全库 | 生成完整诊断报告 |
| **手动触发** | 用户在健康中心点「立即分析」 | 全库或指定范围 | 即时诊断 |

## 处理流程

```
诊断报告生成
    │
    ▼
┌─ 用户查看报告 ────────────────────────────────────────┐
│                                                       │
│  📊 知识库健康度 78%                                   │
│                                                       │
│  🔄 疑似重复 (12 组)                                   │
│  ┌─────────────────────────────────────────────┐     │
│  │ 组 1: "GIL 限制及解决方案" 重复度 0.96       │     │
│  │   ○ chunk_A (文档: python_guide.md, 300字)  │     │
│  │   ○ chunk_B (insight: GIL解决方案, 250字)   │     │
│  │   ○ chunk_C (文档: faq.md, 180字)           │     │
│  │                                              │     │
│  │   → 推荐保留: chunk_A (质量分 0.82)          │     │
│  │   → 其余标记 superseded                      │     │
│  │                                              │     │
│  │   [采纳推荐]  [选 chunk_B]  [选 chunk_C]     │     │
│  │   [都保留但互相链接]  [跳过]                 │     │
│  └─────────────────────────────────────────────┘     │
│                                                       │
│  ⚠️ 低质量 (5 条)                                     │
│  🕐 可能过时 (2 条)                                   │
│  🏝️ 孤岛 (3 条)                                      │
│  🧩 碎片簇 (1 组)                                     │
│                                                       │
│  [逐条处理]  [一键标记已读]  [忽略本周]               │
└───────────────────────────────────────────────────────┘
```

mark superseded 的 chunk 在检索时被排除（where status != 'superseded'），但保留在 DB 不物理删除，可随时恢复。
