# 监控告警系统 — 方案设计

> 状态：✅ 方案已确定 | 创建：2026-06-03 | 关联：[[15-KB智能路由]] [[16-对话知识沉淀]] [[17-Skill集成]] [[18-概念术语关联]] [[19-知识库内容再组织]]

## 定位

为数据治理系统的全部模块提供统一的监控埋点、指标看板和告警能力。日志（loguru → 文件）负责单次排查，监控事件表（PostgreSQL）负责趋势分析和告警。

---

## 核心原则

```
日志  → grep 一行定位，排查单次问题用，详情保留
事件表 → SQL 聚合查询，看趋势/告警用，只存聚合数据
```

## 数据库设计

### `kb_monitor_events` — 统一监控事件表

```sql
CREATE TABLE kb_monitor_events (
    id            BIGSERIAL PRIMARY KEY,
    
    -- 分类
    category      VARCHAR(20) NOT NULL,     -- routing / insight / external / concept / health / system
    
    -- 事件标识
    event         VARCHAR(50) NOT NULL,     -- centroid_hit / llm_route_failed / insight_extracted / ...
    
    -- 关联
    kb_id         INTEGER,                  -- 涉及的 KB
    session_id    VARCHAR(36),              -- 涉及的会话
    
    -- 数值
    value_int     INTEGER,                  -- 整数指标（条数、次数）
    value_float   FLOAT,                    -- 浮点指标（距离、置信度、耗时秒）
    
    -- 状态
    status        VARCHAR(20) NOT NULL DEFAULT 'success',  -- success / failed / warning
    
    -- 消息
    message       VARCHAR(500),             -- 简短描述
    
    -- 详情（扩展字段）
    extra_json    JSONB NOT NULL DEFAULT '{}',
    
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_monitor_category ON kb_monitor_events(category);
CREATE INDEX idx_monitor_event ON kb_monitor_events(event);
CREATE INDEX idx_monitor_time ON kb_monitor_events(created_at);
CREATE INDEX idx_monitor_kb ON kb_monitor_events(kb_id);
CREATE INDEX idx_monitor_status ON kb_monitor_events(status);
```

### 为什么一张表

- 常用查询字段（category/event/kb_id/status/value_int/created_at）都是平铺列，不走 JSONB
- 写入低频：路由 1 次/提问 + 提炼 1 次/天 + 扫描 1 次/周
- 每天 1000 次提问 × 200 字节 ≈ 200KB，存储无压力

## 各模块事件定义

### #15 智能路由

| event | status | 字段 | 说明 |
|-------|--------|------|------|
| `centroid_hit` | success | kb_id, value_float=距离 | 质心匹配命中 |
| `centroid_gap` | warning | extra_json={"top2_kbs":[...]} | 前两名太接近，降级 Layer 2 |
| `centroid_all_miss` | warning | value_float=最近距离 | 所有 KB 距离超阈值 |
| `llm_route_hit` | success | kb_id, value_float=置信度 | LLM 路由命中 |
| `llm_route_miss` | warning | value_float=置信度 | LLM 路由低置信度，降级 Layer 3 |
| `llm_route_failed` | failed | message=错误原因 | LLM 调用失败 |
| `llm_route_invalid_kb_id` | failed | extra_json={"returned_kb_id":N} | LLM 返回不存在的 kb_id |
| `route_fallback` | warning | - | 进入 Layer 3 用户引导 |
| `route_manual` | success | kb_id | 用户手动指定 KB |
| `route_search_all` | success | - | 用户选择全库搜索 |
| `centroid_update_failed` | failed | kb_id, message | 质心计算失败 |
| `route_no_candidates` | warning | - | 所有 KB 无文档，无候选 |

### #16 对话知识沉淀

| event | status | 字段 | 说明 |
|-------|--------|------|------|
| `insight_batch_started` | success | value_int=待处理 QA 数 | 批处理开始 |
| `insight_batch_completed` | success | extra_json={"extracted":N,"skipped":N,"duplicates":N} | 批处理完成 |
| `insight_batch_failed` | failed | message | 批处理失败 |
| `insight_llm_failed` | failed | value_int=失败条数 | LLM 提炼调用失败 |
| `insight_approved` | success | value_int=通过数 | 用户审核通过 |
| `insight_rejected` | success | value_int=拒绝数 | 用户审核拒绝 |
| `insight_assigned` | success | extra_json={"to_kb_id":N,"from_kb_id":N} | 知识点分配到目标 KB |

### #17 Skill 集成

| event | status | 字段 | 说明 |
|-------|--------|------|------|
| `external_push_received` | success | value_int=条数, extra_json={"platform":"claude_code"} | 收到外部推送 |
| `external_push_deduped` | warning | value_int=重复条数 | 推送去重跳过 |
| `external_push_failed` | failed | extra_json={"platform":"..."} | 推送处理失败 |
| `external_api_key_invalid` | failed | message | API Key 无效 |

### #18 概念术语关联

| event | status | 字段 | 说明 |
|-------|--------|------|------|
| `concept_extraction_completed` | success | kb_id, value_int=概念数, value_float=耗时秒 | 概念抽取完成 |
| `concept_extraction_failed` | failed | kb_id, message | 概念抽取失败 |
| `concept_duplicate_merged` | success | kb_id, extra_json={"merged_into":concept_id} | 概念去重合并 |

### #19 知识库内容再组织

| event | status | 字段 | 说明 |
|-------|--------|------|------|
| `health_scan_started` | success | kb_id | 扫描开始 |
| `health_scan_completed` | success | kb_id, extra_json={"health_score":N,"duplicates":N,"low_quality":N,"outdated":N,"orphans":N} | 扫描完成 |
| `health_scan_failed` | failed | kb_id, message | 扫描失败 |
| `health_chunk_superseded` | success | kb_id, value_int=标记数 | 用户确认标记 superseded |
| `health_chunk_merged` | success | kb_id, value_int=合并组数 | 用户确认合并 |

## 告警规则

放在 `system_config` 中：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `alert_llm_route_fail_threshold` | `3` | LLM 路由连续失败 N 次告警 |
| `alert_fallback_rate_threshold` | `0.20` | Layer 3 降级率超过 20% 告警 |
| `alert_centroid_fail` | `true` | 质心计算失败立即告警 |
| `alert_external_push_fail` | `true` | 外部推送失败立即告警 |
| `alert_insight_batch_fail` | `true` | 提炼批处理失败告警 |
| `alert_health_scan_fail` | `true` | 健康扫描失败告警 |
| `alert_concept_extraction_fail` | `true` | 概念抽取失败告警 |

### 告警方式

| 方式 | 说明 |
|------|------|
| **页面内告警** | 监控看板顶部红色告警卡片，展示未解除的告警 |
| **外部通知** | Webhook 推送（支持钉钉/飞书/企业微信），后续可扩展邮件 |
