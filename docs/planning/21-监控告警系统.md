# 监控告警系统 — 方案设计

> 状态：✅ 已实现 | 创建：2026-06-03 | 更新：2026-06-10 | 关联：[[15-KB智能路由]] [[16-对话知识沉淀]] [[17-Skill集成]] [[18-概念术语关联]] [[19-知识库内容再组织]]

## 定位

为数据治理系统的全部模块提供统一的监控埋点、指标看板和告警能力。日志（loguru → 文件）负责单次排查，监控事件表（PostgreSQL）负责趋势分析和告警。

---

## 核心原则

```
日志  → grep 一行定位，排查单次问题用，详情保留
事件表 → SQL 聚合查询，看趋势/告警用，只存聚合数据
```

## 数据库设计

### `kb_monitor_events` — 统一监控事件表

```sql
CREATE TABLE kb_monitor_events (
    id            BIGSERIAL PRIMARY KEY,
    
    -- 分类
    category      VARCHAR(20) NOT NULL,     -- routing / insight / external / concept / health / system
    
    -- 事件标识
    event         VARCHAR(50) NOT NULL,     -- centroid_hit / llm_route_failed / insight_extracted / ...
    
    -- 关联
    kb_id         INTEGER,                  -- 涉及的 KB
    session_id    VARCHAR(36),              -- 涉及的会话
    
    -- 数值
    value_int     INTEGER,                  -- 整数指标（条数、次数）
    value_float   FLOAT,                    -- 浮点指标（距离、置信度、耗时秒）
    
    -- 状态
    status        VARCHAR(20) NOT NULL DEFAULT 'success',  -- success / failed / warning
    
    -- 消息
    message       VARCHAR(500),             -- 简短描述
    
    -- 详情（扩展字段）
    extra_json    JSONB NOT NULL DEFAULT '{}',
    
    -- 告警解除时间（NULL=未解除）
    resolved_at   TIMESTAMPTZ,

    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_monitor_category ON kb_monitor_events(category);
CREATE INDEX idx_monitor_event ON kb_monitor_events(event);
CREATE INDEX idx_monitor_time ON kb_monitor_events(created_at);
CREATE INDEX idx_monitor_kb ON kb_monitor_events(kb_id);
CREATE INDEX idx_monitor_status ON kb_monitor_events(status);
CREATE INDEX idx_monitor_resolved ON kb_monitor_events(resolved_at);
```

### 为什么一张表

- 常用查询字段（category/event/kb_id/status/value_int/created_at）都是平铺列，不走 JSONB
- 写入低频：路由 1 次/提问 + 提炼 1 次/天 + 扫描 1 次/周
- 每天 1000 次提问 × 200 字节 ≈ 200KB，存储无压力
- 看板聚合查询只需 `WHERE category = 'routing'`，优于跨表 JOIN

### 告警解除

不设独立的告警表。在事件行上加 `resolved_at` 字段，NULL 表示活跃告警，非 NULL 表示已解除。API：

- `POST /api/v1/kb/monitor/alerts/{id}/resolve` — 解除单条
- `POST /api/v1/kb/monitor/alerts/resolve-all` — 全部已读

## 各模块事件定义

### 智能路由（`category = 'routing'`）

| event | status | 字段 | 说明 |
|-------|--------|------|------|
| `centroid_hit` | success | kb_id, value_float=距离 | 质心匹配命中 |
| `llm_route_hit` | success | kb_id, value_float=置信度 | LLM 路由命中 |
| `llm_route_miss` | warning | kb_id, value_float=置信度 | LLM 路由低置信度，降级 Layer 3 |
| `llm_route_failed` | failed | message=错误原因 | LLM 路由调用异常 |
| `llm_route_parse_failed` | warning | message=LLM 返回内容 | LLM 返回无法解析 |
| `llm_route_invalid_kb_id` | failed | value_int=返回的 kb_id | LLM 返回不存在的 kb_id |
| `route_fallback` | warning | session_id | 进入 Layer 3 用户引导 |
| `route_manual` | success | kb_id | 用户手动指定 KB |
| `route_invalid_kb_id` | warning | value_int=指定的 kb_id | 用户指定的 KB 不存在 |
| `centroid_update_failed` | failed | kb_id, message | 质心计算失败 |
| `route_no_candidates` | warning | - | 所有 KB 无文档，无候选 |

### 对话知识沉淀（`category = 'insight'`）

| event | status | 字段 | 说明 |
|-------|--------|------|------|
| `insight_batch_started` | success | value_int=待处理 QA 数, extra_json | 批处理开始 |
| `insight_batch_completed` | success/warning | value_int=提取数, value_float=耗时秒 | 批处理完成（errors>0 时 status=warning） |
| `insight_llm_failed` | failed | value_int=insight_id, message | 后台单条提炼 LLM 失败 |
| `insight_bg_processing_failed` | failed | value_int=insight_id, message | 后台提炼异常崩溃 |

### Skill 集成（`category = 'external'`）

| event | status | 字段 | 说明 |
|-------|--------|------|------|
| `external_push_received` | success | value_int=条数, extra_json={"platform":"claude_code","skipped":N,"rejected":N} | 收到外部推送 |
| `external_push_failed` | failed | extra_json={"platform":"..."} | 推送处理失败 |

### 概念术语关联（`category = 'concept'`）

| event | status | 字段 | 说明 |
|-------|--------|------|------|
| `concept_extraction_completed` | success | value_int=概念数, extra_json={"chunks":N,"created":N,"updated":N} | 概念抽取完成 |
| `concept_extraction_failed` | failed | kb_id, message, extra_json={"chunk_id":N} | 单 chunk LLM 抽取失败 |
| `concept_commit_failed` | failed | kb_id, message, extra_json={"chunk_id":N} | 概念入库失败 |

### 知识库健康扫描（`category = 'health'`）

| event | status | 字段 | 说明 |
|-------|--------|------|------|
| `health_scan_started` | success | kb_id, extra_json={"scan_type":"scheduled/manual/ingestion"} | 扫描开始 |
| `health_scan_completed` | success | kb_id, value_float=健康分, extra_json | 扫描完成 |
| `health_scan_failed` | failed | kb_id, message | 扫描过程异常 |

### 系统事件（`category = 'system'`）

LLM 调用和文档摄入归入 `system` 分类：

| event | status | 字段 | 说明 |
|-------|--------|------|------|
| `llm_call_completed` | success | session_id, value_float=耗时秒, value_int=估算token, extra_json={"input_tokens":N,"output_tokens":N,"model":"...","provider":"..."} | LLM 生成完成 |
| `llm_generation_failed` | failed | session_id, message | LLM 生成异常 |
| `embedding_failed` | failed | session_id, message | Embedding 调用异常 |
| `rerank_failed` | warning | session_id | Reranker 不可用，退化为原始排序 |
| `doc_uploaded` | success | kb_id, value_int=1, extra_json={"doc_name":"...","doc_type":"..."} | 文档上传成功 |
| `doc_ingestion_completed` | success | kb_id, value_int=chunk数, extra_json={"doc_id":N,"doc_type":"..."} | 文档摄入完成 |
| `doc_ingestion_failed` | failed | value_int=doc_id, message | 文档摄入异常 |

## 告警规则

放在 `system_config` 中：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `alert_llm_route_fail_threshold` | `3` | LLM 路由连续失败 N 次告警 |
| `alert_fallback_rate_threshold` | `0.20` | Layer 3 降级率超过 20% 告警 |
| `alert_centroid_fail` | `true` | 质心计算失败立即告警 |
| `alert_external_push_fail` | `true` | 外部推送失败立即告警 |
| `alert_insight_batch_fail` | `true` | 提炼批处理失败告警 |
| `alert_health_scan_fail` | `true` | 健康扫描失败告警 |
| `alert_concept_extraction_fail` | `true` | 概念抽取失败告警 |
| `alert_slow_call_threshold` | `5.0` | LLM 慢调用阈值（秒） |

规则检查 API `GET /api/v1/kb/monitor/alerts` 实时执行。

### 告警方式

| 方式 | 状态 | 说明 |
|------|------|------|
| **页面内告警** | ✅ 已实现 | 看板顶部折叠告警条，展开后单条 ✕ 解除，支持全部已读 |
| **外部通知** | ⏳ 后续 | Webhook 推送（支持钉钉/飞书/企业微信），可扩展邮件 |

## 埋点策略

`write_event()` 只调 `db.flush()`，由上层业务 `db.commit()` 提交。需要确保所有 `return` 分支都有 commit 或 rollback，否则 async generator 中途退出会导致已 flush 的事件丢失。

### 埋点覆盖

| 文件 | 写入事件 | 说明 |
|------|---------|------|
| `services/kb_router.py` | centroid_hit / llm_route_miss / llm_route_failed / llm_route_parse_failed / llm_route_invalid_kb_id / route_invalid_kb_id | 路由全路径 |
| `services/chat_service.py` | centroid_hit / llm_route_hit / route_fallback / route_manual / llm_call_completed / llm_generation_failed / embedding_failed / rerank_failed | 路由 + LLM 调用 + 异常 |
| `services/insight_service.py` | insight_batch_started / insight_batch_completed / insight_llm_failed / insight_bg_processing_failed | 批处理 + 后台 |
| `services/concept_service.py` | concept_extraction_completed / concept_extraction_failed / concept_commit_failed | 抽取 + 入库 |
| `services/health_service.py` | health_scan_started / health_scan_completed / health_scan_failed | 扫描全周期 |
