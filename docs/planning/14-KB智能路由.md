# KB 智能路由 — 三层匹配设计

> 状态：✅ 已实现 | 更新：2026-06-11 | 版本：v0.5.0 已落地

## 问题

当前对话固定走一个 KB（session.kb_id 或默认 id=1），用户需手动切换知识库。聊天页 header 显示「关联 N 个本地知识库」会误导用户以为跨库检索。

## 目标

两层用户交互 + 三层后端匹配：

```
用户主动选了 KB → 直接用，不走匹配
       ↓ 没选（默认"自动"模式）
三层降级匹配 → Layer 1 质心 → Layer 2 LLM 路由 → Layer 3 用户引导
```

---

## 三层路由架构

```
用户提问 "GIL 锁怎么解决"
    │
    ▼
┌─ Layer 1：质心向量匹配（< 1ms，零成本）────────────────┐
│                                                        │
│  SELECT kb_id, centroid <=> question_vec AS dist       │
│  FROM kb_knowledge_bases                               │
│  WHERE centroid_embedding IS NOT NULL                  │
│  ORDER BY dist LIMIT 1                                 │
│                                                        │
│  dist ≤ centroid_threshold  → ✅ 命中，直接用           │
│  dist > centroid_threshold  → ❌ 降级 Layer 2           │
│  无质心的 KB              → 跳过（冷 KB）               │
│                                                        │
│  预估命中率：日常问答 80-90%                             │
│                                                        │
│  命中后通过 thinking 流输出匹配结果，用户可感知            │
└────────────────────────────────────────────────────────┘
    │ 命中 —— thinking 流：{"phase":"routing","kb_name":"Python 技术文档","method":"centroid"}
    │ 未命中 ↓
    ▼
┌─ Layer 2：LLM 智能路由（~200-500ms，一次轻量调用）─────┐
│                                                        │
│  使用和问答相同的 LLM provider/model，temperature=0      │
│  不走流式，纯结构化返回                                  │
│                                                        │
│  System: 你是知识库路由助手，根据用户问题选择最匹配的 KB  │
│  User:                                                  │
│    问题：「GIL 锁怎么解决」                               │
│    可选知识库：                                          │
│      1. Python 技术文档 — 核心概念：GIL, 装饰器, asyncio  │
│      2. 产品 PRD — 核心概念：用户故事, 需求评审, 迭代     │
│      3. 运维手册 — 核心概念：Docker, nginx, 日志轮转      │
│    请返回 JSON: {"kb_id": 1, "confidence": 0.85}        │
│                                                        │
│  （概念标签来自 #18 的概念抽取，无概念数据时退化为         │
│   只展示 name + description）                            │
│                                                        │
│  confidence ≥ route_threshold  → ✅ 命中                │
│  confidence < route_threshold  → ❌ 降级 Layer 3         │
└────────────────────────────────────────────────────────┘
    │ 命中
    │ 未命中 ↓
    ▼
┌─ Layer 3：用户引导 ────────────────────────────────────┐
│                                                        │
│  前端展示：                                              │
│  "🤔 我不太确定该用哪个知识库来回答这个问题。              │
│   你可以：                                               │
│   [指定「Python 技术文档」]  [指定「运维手册」] ...       │
│   [搜索全部知识库]         [换个方式描述问题]             │
│                                                        │
│  用户选择 → 重新走对应 KB 检索                           │
└────────────────────────────────────────────────────────┘
```

## 容错与兜底

> 路由不能出错。每种异常情况都有明确的兜底路径。

### 全量异常覆盖

| # | 情况 | 后果 | 兜底方案 |
|---|------|------|---------|
| 1 | 所有 KB 都没有文档 | 路由无候选 | 前置检查 chunk 总数 = 0 → 直接返回"请先上传文档"，不走路由 |
| 2 | 多个 KB 内容重叠 | 向量距离接近，可能选错 | gap 规则：第一名和第二名差距 < 0.08 → 降级 Layer 2 LLM 判断 |
| 3 | 用户问题太模糊 | 和所有 KB 距离都远 | Layer 1 全不命中 → Layer 2 LLM 低置信度 → Layer 3 引导用户换描述 |
| 4 | 问题和所有 KB 不相关 | 强选一个结果不对 | Layer 2 判断全部不相关 → Layer 3 引导全库搜索或换问题 |
| 5 | LLM 路由调用失败 | 网络、token 耗尽 | try/catch → 跳过 Layer 2 → 用 Layer 1 最佳结果或直接 Layer 3 |
| 6 | LLM 返回不存在的 kb_id | 幻觉 | 写入前 db.get(KnowledgeBase, kb_id) 校验，不存在则降级 Layer 3 |
| 7 | 质心计算出错 | 除零、空值 | 计算函数内部防护：chunk_count=0 → 质心设 NULL；异常 → 保持旧值，记录日志 |
| 8 | KB 被删但路由还在引用 | 查已删除的库 | 路由完成后检索前再次 db.get 验证 KB 存在，不存在则重新路由 |
| 9 | 前端状态和后端不一致 | 前端显示自动但实际指定了 KB | 后端以收到的 kb_id 参数为准（null=路由，N=指定，0=全库），前端只是展示 |

### 核心原则

```
每一层都有下一层兜底
  Layer 1 失败 → Layer 2
  Layer 2 失败 → Layer 3
  Layer 3 让用户自己决定

任何异常都不崩溃
  catch → 降级 → 日志记录 → 继续走下一层
```

### 各层防护细节

**Layer 1 防护：**

```python
async def match_kb_by_centroid(db, question_embedding, threshold, gap):
    # 排除沉积库、排除无质心的 KB
    rows = await db.execute(
        select(KbKnowledgeBase)
        .where(
            KbKnowledgeBase.centroid_embedding.is_not(None),
            KbKnowledgeBase.kb_type != "deposition",
        )
    )
    kbs = rows.all()
    
    if not kbs:
        return None  # 无候选 → 降级 Layer 2
    
    # 计算余弦距离
    results = []
    for kb in kbs:
        dist = cosine_distance(kb.centroid_embedding, question_embedding)
        results.append((kb, dist))
    
    results.sort(key=lambda x: x[1])
    first, second = results[0], results[1] if len(results) > 1 else (None, None)
    
    if first[1] > threshold:
        return None  # 第一名也太远 → 降级 Layer 2
    
    if second and (second[1] - first[1]) < gap:
        return None  # 前两名太接近 → 降级 Layer 2 语义判断
    
    return {"kb_id": first[0].id, "kb_name": first[0].name, 
            "distance": round(first[1], 4), "method": "centroid"}
```

**Layer 2 防护：**

```python
async def route_kb_by_llm(db, question, kbs):
    try:
        response = await llm_call_non_stream(
            system="你是知识库路由助手...",
            user_prompt=build_route_prompt(question, kbs),
            temperature=0,
        )
        result = parse_json(response)
        
        # 校验返回的 kb_id 真实存在
        kb = await db.get(KnowledgeBase, result["kb_id"])
        if kb is None or kb.kb_type == "deposition":
            return None  # LLM 幻觉 → 降级 Layer 3
        
        if result["confidence"] < route_llm_confidence:
            return None  # 低置信度 → 降级 Layer 3
        
        return {"kb_id": kb.id, "kb_name": kb.name,
                "confidence": result["confidence"], "method": "llm_route"}
    
    except Exception:
        logger.error(f"llm_route_failed question_len={len(question)}")
        return None  # 任何异常 → 降级 Layer 3
```

**主流程防护：**

```python
async def resolve_kb(db, question, question_embedding, kb_id):
    # 用户明确指定 → 直接验证后用
    if kb_id is not None and kb_id > 0:
        kb = await db.get(KnowledgeBase, kb_id)
        if kb is not None and kb.kb_type != "deposition":
            return kb
        # 指定的 KB 不存在 → 回退路由
    
    # kb_id=0 → 全库搜索
    if kb_id == 0:
        return None  # 调用方走全库检索
    
    # kb_id=null → 三层路由
    # Layer 1
    result = await match_kb_by_centroid(db, question_embedding, ...)
    if result:
        yield thinking_event(result)
        return await db.get(KnowledgeBase, result["kb_id"])
    
    # Layer 2
    kbs = await get_route_candidates(db)  # 排除沉积库、空库
    result = await route_kb_by_llm(db, question, kbs)
    if result:
        yield thinking_event(result)
        return await db.get(KnowledgeBase, result["kb_id"])
    
    # Layer 3 — 引导用户
    return None  # 调用方返回引导消息给前端
```

**质心计算防护：**

```python
async def update_centroid(db, kb_id):
    chunk_count = await db.scalar(
        select(func.count()).select_from(KbChunk)
        .join(KbDocument).where(KbDocument.kb_id == kb_id, KbDocument.deleted_at.is_(None))
    )
    
    # 冷 KB：无 chunk → 质心 NULL
    if chunk_count == 0:
        kb = await db.get(KnowledgeBase, kb_id)
        kb.centroid_embedding = None
        kb.centroid_updated_at = func.now()
        await db.commit()
        return
    
    try:
        # 采样计算，避免大 KB 全表扫描
        centroid = await compute_centroid_sample(db, kb_id, sample_size=1000)
        kb = await db.get(KnowledgeBase, kb_id)
        kb.centroid_embedding = centroid
        kb.centroid_updated_at = func.now()
        await db.commit()
    except Exception:
        logger.error(f"centroid_update_failed kb_id={kb_id}")
        # 保持旧值，不影响路由（旧质心可能不准，但不会崩溃）
```

## 关键设计决策

### Layer 2 LLM 配置

| 决策 | 结论 |
|------|------|
| 模型 | 和问答用同一个 provider/model（从 `system_config` 读取），无需额外配置 |
| 调用方式 | 非流式，temperature=0，要求返回结构化 JSON |
| 输入 | 用户问题 + 所有 KB 的 name + description |
| 输出 | `{ "kb_id": int, "confidence": float }` |

### 质心向量维护

| 决策 | 结论 |
|------|------|
| 新增 chunk | **增量更新**：`(old_centroid × N + new_embedding) / (N + 1)`，O(1)，< 1ms |
| 删除 chunk | **采样重算**：随机采样 1000 个 chunk 计算均值，O(1000)，~10ms，误差 < 1% |
| 冷 KB | 无 chunk → 质心为 NULL → Layer 1 自动跳过 |
| 存储 | `kb_knowledge_bases.centroid_embedding vector(1024)` + `centroid_updated_at` |
| 容错 | 计算失败 → 保持旧值，记录日志；不影响路由流程 |

### 可配置阈值

放在 `system_config` 表中，系统级全局唯一，支持运行时热更新：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `route_centroid_threshold` | `0.40` | Layer 1 质心匹配阈值（余弦距离，越小越严格） |
| `route_centroid_gap` | `0.08` | Layer 1 前两名差距阈值，小于此值视为太接近，降级 Layer 2 |
| `route_llm_confidence` | `0.60` | Layer 2 LLM 路由置信度阈值 |

### 用户交互规则

| 用户选择 | 后端行为 | 持久化 |
|---------|---------|--------|
| 「自动」（默认） | `kb_id=null` → 走三层匹配 | 无，新建会话重置 |
| 指定 KB（如「Python 技术文档」） | `kb_id=N` → 直接检索该 KB | 仅当前会话有效 |
| 「全库搜索」 | `kb_id=0` → 跨所有 KB 检索 | 仅当前会话有效 |

> **关键行为**：新建会话时 KB 选择器始终回到「自动」。用户主动选的 KB 不会带到下一个会话。这避免了用户选了某个 KB 后忘记切回，导致新问题搜错库。

### 匹配结果如何感知

匹配信息通过 **已有的 thinking SSE 流** 输出，不需要额外 UI 组件：

```json
// Layer 1 命中
{"phase": "routing", "message": "质心匹配: Python 技术文档 (距离 0.23)", "kb_id": 2, "kb_name": "Python 技术文档", "method": "centroid", "confidence": 0.77}

// Layer 2 命中
{"phase": "routing", "message": "LLM 路由: 运维手册 (置信度 0.85)", "kb_id": 3, "kb_name": "运维手册", "method": "llm_route", "confidence": 0.85}

// Layer 3 未命中
{"phase": "routing", "message": "未能确定匹配知识库，请手动选择", "method": "fallback", "confidence": 0}
```

用户在前端看到推理过程中出现 "质心匹配: Python 技术文档 (距离 0.23)" 或 "LLM 路由: 运维手册 (置信度 0.85)"，就知道系统自动选了哪个 KB，无需额外操作。不认同时可以手动切换下拉框选其他 KB 重新提问。
