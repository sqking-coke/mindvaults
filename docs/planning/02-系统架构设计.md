## 3. 核心数据流

### 3.1 文档入库流程

```
POST /api/v1/kb/documents?kb_id=X
  → 文件校验（类型/大小）
    → 写入磁盘 (UUID 文件名)
      → 创建 KbDocument 记录 (kb_id=X, status=PROCESSING)
        → 异步摄入管道:
          ① parser: 解析文本 (PDF/Word/MD/TXT)
          ② chunker: 固定大小切片 (chunk_size/chunk_overlap)
          ③ embedder: BGE-M3 1024维向量化
          ④ 写入 kb_chunks (embedding 列 pgvector)
          ⑤ 更新 document.status=COMPLETED
```

### 3.2 RAG 问答流程

```
POST /api/v1/kb/chat { question, session_id }
  → SSE progress: intent      "正在理解问题..."
  → SSE progress: retrieval   "正在向量化问题..."
  → embed_text(question) → 1024维向量
  → retrieve_chunks(kb_id=X)  → pgvector HNSW 搜索
  → SSE progress: matching    "已匹配 N 条相关片段"
  → SSE progress: matching    " -> [1] doc_name (匹配度: XX%)"
  → SSE progress: generating  "正在调用大模型..."
  → generate_stream(system_prompt, user_prompt_with_context)
    → SSE token × N           打字机流式输出
  → SSE done: { ref_chunks }  引用溯源
  → 保存 KbQaRecord
```

### 3.3 检索流程

```
retrieve_chunks(db, query_embedding, kb_id=None)
  → 加载 kb_config (按 kb_id 取对应配置，NULL 用全局)
  → 检查 Redis 缓存
  → pgvector 查询:
      SELECT c.*, d.doc_name, d.page,
             1 - (c.embedding <=> query) AS similarity
      FROM kb_chunks c
      JOIN kb_documents d ON c.document_id = d.id
      WHERE d.deleted_at IS NULL
        AND d.status = 2               -- COMPLETED
        AND d.kb_id = :kb_id           -- ★ KB 隔离
      ORDER BY similarity DESC
      LIMIT :top_k
  → 回写 Redis 缓存
```

## 4. 关键设计原则

- **同步请求轻量化**：文档上传只写元数据 + 触发异步摄入，不阻塞 HTTP 响应
- **SSE 透传全链路**：progress / token / done / error 四种事件贯穿问答全流程
- **配置热更新**：修改 `kb_config` 后下次请求立即生效，无需重启
- **KB 级隔离**：文档归属 KB → 切片通过文档间接归属 → 检索限定 KB → 会话绑定 KB
