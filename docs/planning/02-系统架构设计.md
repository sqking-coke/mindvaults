## 3. 核心数据流

### 3.1 文档入库流程（v0.8.0 更新）

```
POST /api/v1/kb/documents?kb_id=X
  → 文件校验（类型/大小）
    → 写入磁盘 (UUID 文件名)
      → 创建 KbDocument 记录 (kb_id=X, status=PROCESSING)
        → 异步摄入管道:
          ① parser: 解析文本 (PDF/Word/MD/TXT) → [(text, page_number)]
          ② preprocessor: 分类型清洗 🆕
             MD:  YAML frontmatter → Section 树 → 弹性映射 (350-650 chars)
             PDF: 跨页页眉检测 → 逐页清洗 → 公共归拢
             TXT: chardet 编码检测 → 噪声过滤 → 归拢
          ③ chunker: semantic 语义切片
          ④ quality_filter: 碎片过滤（< 50 字符、box 残留）
          ⑤ embedder: BGE-M3 1024维向量化
          ⑥ 写入 kb_chunks (embedding 列 pgvector)
          ⑦ 更新 document.status=COMPLETED
          ⑧ 触发概念抽取（v0.7.0） + 健康扫描（v0.6.0）
```

### 3.2 RAG 问答流程（v0.5.0 更新）

```
POST /api/v1/kb/chat { question, session_id }
  → SSE progress: intent        "正在理解问题..."
  → SSE progress: routing       "正在匹配知识库..."  🆕
      → Layer 1: 质心向量匹配 (< 1ms)
      → Layer 2: LLM 智能路由 (未命中时)
      → Layer 3: 用户引导 (降级)
      → 概念定义注入上下文（v0.7.0）
  → SSE progress: retrieval     "正在向量化问题..."
  → embed_text(question) → 1024维向量
  → retrieve_chunks(kb_id=X)  → pgvector HNSW 搜索
  → SSE progress: matching      "已匹配 N 条相关片段"
  → SSE progress: matching      " -> [1] doc_name (匹配度: XX%)"
  → SSE progress: generating    "正在调用大模型..."
  → generate_stream(system_prompt, user_prompt_with_context)
    → SSE token × N             打字机流式输出
  → SSE done: { ref_chunks }    引用溯源
  → 保存 KbQaRecord
  → 触发监控事件写入（v0.9.0）
```

### 3.3 知识沉淀流程（v0.5.0）

```
定时批处理（每日凌晨 2:00）:
  未提炼 QA 对 → LLM 提炼知识点 → 去重（ID + 向量）
    → kb_insights (status=pending) → 用户审核
      → 通过 → embed + 入库，可被检索命中
      → 拒绝 → 标记 rejected

外部推送（Skill 插件，实时）:
  Claude Code 对话结束 → POST /api/v1/kb/external/push
    → kb_external_entries → 定时提炼 → 审核 → 分配目标 KB
```

### 3.4 概念术语关联（v0.7.0）

```
文档摄入完成 → 触发概念抽取:
  chunk → LLM 提取术语 + 生成定义
    → kb_concepts (name + definition + embedding)
    → kb_chunk_concepts (chunk ↔ concept 关联)

RAG 检索时:
  命中 chunk → 查询关联概念 → 定义注入 LLM 上下文

前端交互:
  文档/回答中术语下划线 → hover 弹概念卡片 → 显示定义+相关概念
```

### 3.5 检索流程

```
retrieve_chunks(db, query_embedding, kb_id=None)
  → 加载 kb_config (按 kb_id 取对应配置，NULL 用全局)
  → 检查 Redis 缓存
  → pgvector 查询:
      SELECT c.*, d.doc_name, d.page,
             1 - (c.embedding <=> query) AS similarity
      FROM kb_chunks c
      JOIN kb_documents d ON c.document_id = d.id
      WHERE d.deleted_at IS NULL
        AND d.status = 2               -- COMPLETED
        AND d.kb_id = :kb_id           -- ★ KB 隔离
      ORDER BY similarity DESC
      LIMIT :top_k
  → 回写 Redis 缓存
```

## 4. 关键设计原则

- **同步请求轻量化**：文档上传只写元数据 + 触发异步摄入，不阻塞 HTTP 响应
- **SSE 透传全链路**：progress / token / done / error 四种事件贯穿问答全流程
- **配置热更新**：修改 `kb_config` 后下次请求立即生效，无需重启
- **KB 级隔离**：文档归属 KB → 切片通过文档间接归属 → 检索限定 KB → 会话绑定 KB
- **源头治理**：预处理管道在摄入时清洗文档，减少事后清理负担（v0.8.0）
- **统一监控**：所有模块通过 `kb_monitor_events` 统一埋点，日志负责排查、事件表负责趋势（v0.9.0）
- **数据沉淀闭环**：QA → 提炼 → 审核 → 入库 → 可检索（v0.5.0）
- **概念语义增强**：术语定义注入 LLM 上下文，提升回答准确性（v0.7.0）
